# Version 0.1.1

A maintenance release for Provider Standard v1. All six npm packages are released together at 0.1.1.
The wire protocol, USDC asset and network identifiers are unchanged.

## Payment safety

Configured verification limits now fail closed [V1]. Applications using `minVerificationScore` or
`stellar.minProviderLevel` must install a trusted `verificationSource` in `PaymentClientOptions`.
Missing, stale, mismatched or unreadable evidence blocks a new payment before signing. The source must
authenticate its validator and bind its evidence to the network, payee, agent and canonical manifest hash.

`minVerificationScore` is a maximum allowed risk score: lower is safer. It is separate from the verifier's
higher-is-better conformance score. A policy without verification limits needs no source. Recovery still
collects an existing job without verification-source access or another payment [J11], [J13].

## Waiting for reconciliation

`provider-kit try` now waits for the provider to reconcile the original `payment_uncertain` job within its
existing follow deadline. The payment client exposes this as `followPaymentUncertain: true`; its default
still returns uncertainty immediately. The verifier's paid checks also wait within their existing deadline.
No waiting path signs or submits a replacement payment [J11], [J13]. Unresolved uncertainty remains unknown.

The sample limits its on-success text-statistics work to one job at a time and refuses excess work before
payment [Q2], [Q3]. It also exposes a readiness endpoint and an optional bind address for the Oracle deployment.

## Verification

The [registered Oracle testnet sample](../../evidence/validation/README.md) passed all C1–C7 checks at level 3,
score 100, and its Validation Registry response anchors the canonical receipt. This is project-operated
verification; independent provider/user pilot acceptance remains outstanding.

The existing before/after Linux client record and historical verification receipts retain their original
versions and outcomes. They are evidence of those captures, not claims that 0.1.1 had already been published.
Release and live CI results are linked from the GitHub release.

## Updating

Update the packages together. Generated projects at 0.1.1 depend on Provider Kit 0.1.1:

```bash
npm install @stellar-agent-services/provider-kit@0.1.1
npm install @stellar-agent-services/payment-client@0.1.1
npm create stellar-service@0.1.1 my-service -- --kind typescript
```

Applications that configure verification limits must supply the trusted source described above before
making a new payment. No built-in registry/risk-source adapter is included.
